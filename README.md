# 加速账本

将串行阶段优化换算成同一工作量的整体耗时，反推只修改一个阶段时达到目标需要的倍数。静态网页，无模型调用或外部依赖。

## 运行

`python3 -m http.server 8768` 后访问 http://127.0.0.1:8768/ 。源码修改后执行 `node build.cjs`，核心验证 `node --test tests/core.test.cjs`。index.html内联core.js与ui.js，无需构建服务器。双击本地HTML未在本次浏览器中验证，推荐HTTP访问。

## 输入与公式

1–8阶段，每个阶段原耗时0–10000000秒、倍数0.1–1000，至少一个原耗时为正。名称1–24个Unicode码点。新增开销0–10000000秒、目标1–1000倍，数值至多3位小数。输入不合法时不显示旧结果、不导出误导数据。新增固定开销只用于新方案，旧有开销应在原阶段中计入。

T0=Σt；T1=Σ(t/s)+H；整体加速比=T0/T1。只优化j阶段时，固定部分B=Σ(i≠j,t_i/s_i)+H。若T0/目标≤B，目标没有有限倍数解；否则所需倍数=t_j/(T0/目标−B)，应用时向上取到0.001。超出1000倍时不应用。假设固定工作量、各阶段串行、运行时没有重叠及负载变化；不用于吞吐和排队模型，不代表任何硬件实测性能。

默认虚构示例1000→720秒，整体1.3888889倍，减少28%；GPU7.5倍才能让整体达到2倍。代码保留精度，界面显示值舍入。

默认不持久化，主动勾选后才将有效方案存入当前站点localStorage，取消勾选移除。JSON导出用于备份与导入，CSV用于逐段对账，PNG用于分享。输入本地处理；托管平台接收普通页面请求。结果卡包含阶段名，分享前检查内容。
